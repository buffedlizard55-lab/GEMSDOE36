Brief

What the challenge asks.

Submit one single-band float32 GeoTIFF on the official 100 m UTM Zone 11N grid, with probabilities in [0,1]. Only one final file is used across the two prize rounds.

Scoring

Distance-weighted Tversky

The official page specifies α = 0.2, β = 0.8, and a triangular kernel with 300 m support. It also requires null/NaN outside the data bounds. The local template—not guessed dimensions—must define the grid and valid mask.

Research lead · unvalidated

Stress-informed geophysical lineaments

Test multiscale fault evidence with a local, uncertainty-weighted orientation penalty inside the differentiable objective. The code is a training scaffold; no competition data or measured benefit is available.

Known-fault scoring clarification: DrivenData staff state that pixels corresponding to existing USGS/INGENIOUS faults are masked from scoring, including re-evaluation. Do not assume that a hard 200 m exclusion is safe: a nearby but distinct hidden trace may still earn credit under the 300 m metric.

Exact submission instructions

The gated path from data to upload.

Follow these steps in order. Do not generate or use the weekly submission slot until the candidate beats the best comparable spatial holdout in this project.

  1. Obtain official files through an enrolled session

    Use the official data page after accepting the rules. Place the feature raster, label rasters/vectors and sample_submission.tif under ignored data/raw/. Do not share credentials or copy data from another participant's repository.

  2. Audit the organizer grid before modeling

    python scripts/audit_inputs.py \
  --features data/raw/training_features.tif \
  --labels data/raw/labels.tif \
  --template data/raw/sample_submission.tif

    Replace the labels filename with the exact authorized file. Confirm band metadata and masks; use the sample template's valid mask, not feature-band NoData.

  3. Beat the current local holdout best

    Reproduce the organizer reference and compare a new candidate on matched spatial blocks, grouped fault systems where possible, a 30-pixel training collar, and exact DTI. Report pooled and every-fold scores, paired spatial-block uncertainty, fixed prediction budget, failed ablations and proxy limitations. The research register is here; there is currently no local holdout best to beat.

  4. Run QA, then build only the selected prediction

    Install the project and run the synthetic checks. After the real holdout gate passes, save this project's final full-grid probabilities as a 2-D NumPy .npy array and run:

    python scripts/build_submission.py outputs/prediction.npy \
  --template data/raw/sample_submission.tif \
  --submission-name "GEMS36-H1-UNIQUE-RUN-ID" \
  --note "Method and measured spatial-holdout result; concise limitation."

    Replace the example name/note with unique and truthful values. The builder prints the exact collision-resistant TIFF path and writes a JSON manifest. It does not claim scientific validity.

  5. Validate that exact file's bytes

    Copy the path printed by the builder and run:

    python scripts/validate_submission.py \
  outputs/submissions/PASTE_THE_PRINTED_FILENAME_HERE.tif \
  --template data/raw/sample_submission.tif --json

    Require PASS; confirm one float32 band, exact grid/CRS/transform, finite in-bounds [0,1] values, NaN/null outside and matching manifest hash. Any local PASS is not proof of organizer acceptance.

  6. Upload manually and preserve evidence

    Read the current official rules, paste the exact unique submission name and short note, upload only the validated file, and preserve the platform receipt. The September 2026 rules allow at most three feedback submissions per week and require one final file for both prize rounds; recheck the current rules before acting.
